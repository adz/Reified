# Reified 0.12.0

Reified 0.12.0 builds every runtime library reflection-free, gives the public error types explicit readable text,
and adds layered configuration to `Reified.Data`: environment variables as `Data`, and a deep merge that combines a
file, the environment, and the command line before one schema parse.

## Breaking changes

- Public records and unions without an explicit `ToString` print only their type name, because the libraries now
  compile with `--reflectionfree`. Reified's public error, failure, issue, violation, and mismatch types provide
  explicit readable text instead: contract and migration errors, schema issues, data patch and comparison failures,
  `ParseError`, and HTTP problem details. Code that relied on structural `string value` output should call the type's
  `ToString` or its renderer. `%A` formatting in your own code is unaffected.
- `Violation.ToString` has explicit debug text retaining the key and arguments of a described violation.
  `Violation.render` is unchanged: it joins `All` with `"; "` and `Any` with `", or "`, without message keys/arguments.
- `SchemaErrors.ToString()` renders one line per issue, the same text as `SchemaErrors.toString`.
- CLI option names now nest on `:` and `__` by default: `--Db:Port 5432` / `--Db__Port=5432` address `Db.Port`.
  Rename literal keys containing those separators or pass prebuilt Data instead. Dots remain literal. Canonical
  indexes, empty-segment rejection and default conversion bounds also apply to CLI; repeated/positional lists count
  toward the budgets. Repeated equivalent paths retain argument order; sections beat scalar prefixes.
- `SchemaShape.Secret` is a new opaque inspection case. Custom metadata interpreters must withhold the payload,
  not treat it as a transparent refinement; generation must fail closed when its hidden schema is required.
- Configuration conversion (`ofConfiguration`, `ofConfigurationPairs`) now bounds sparse expansion: 10,000 items per
  list, 100,000 output nodes across the result (including root, containers, leaves and null gaps), and 64 input path
  segments. Exceeding a limit throws `ArgumentException` with the path and limit, before oversized list allocation.
  For larger trusted inputs, migrate to `Data.ofConfigurationWith` and explicitly adjust positive limits.
- Configuration list indexes must now be canonical ASCII decimal names: `0` or `[1-9][0-9]*`. Noncanonical names
  such as `00`, `+1`, `0x10` and `1_0` remain object fields, consistently on .NET/Fable, instead of aliasing an index
  and potentially losing a subtree. Rename intended indexes to canonical spelling and resolve conflicting paths
  before conversion. Canonical numeric indexes beyond the configured bound, including beyond Int32, are rejected.

## Added

- `Data.merge` and `Data.mergeAll`: right-biased deep merge. Objects merge by name at every depth, keeping first-seen
  field order and appending new names; lists, scalars, and `Data.Null` on the right replace the left. A later `null`
  overrides a key to `Data.Null` and never removes it. `mergeAll` folds left from `Data.Object []`.
- `Data.ofEnvironment` and `Data.ofEnvironmentWith`, with `DataEnvironmentOptions` (`Prefix`, `Separator`, `Limits`): nested
  `Data` from environment variable pairs the caller supplies, split on `__` by default. Names keep their case,
  canonical numeric sections become bounded lists as in `Data.ofConfiguration`, names apply in ordinal order so a
  section always beats a value of the same name, and names with an empty segment are skipped. Values are text or
  null. Set `Limits` explicitly for larger trusted inputs; defaults match configuration conversion.
- `DataConversionLimits` (`MaxCollectionLength`, `MaxExpandedNodes`, `MaxDepth`) and `Data.ofConfigurationWith`:
  configure positive conversion bounds. All nested lists share the complete output-node budget.

- `Schema.ignoreKeyCase` configures ordinal-ignore-case record field/alias matching at every model depth, opt-in
  through `Schema.parseWith`; the default stays case-sensitive. Equivalent input names merge recursively in order,
  retaining first spelling/position and later values. Case-colliding schema names/aliases report `field.case.ambiguous`.
- `Data.mergeWith`, `mergeAllWith` and portable `Data.ordinalIgnoreCase`: apply key comparison while folding layers.
  Use the comparer during each merge and the matching Schema parse option; parsing cannot reconstruct precedence
  already lost by exact-name merging across mixed-case sources. Default merges are unchanged.
- `Secret<'value>` in `Reified.Refinements`: sealed reference-equality values, redacted display, explicit
  `Secret.create` / `Secret.reveal`. Canonical field inference and `Schema.secret` / `secretWith` wrap payload schemas.
  Parse/check failures become value-free `secret.invalid` issues at the secret field path; codec errors and retained
  inputs are redacted. JSON encoding writes `"<redacted>"`, never the payload; decoding still accepts the underlying
  wire shape, so secret codecs intentionally do not round trip. Inspection hides payload metadata; JSON Schema marks
  it write-only/opaque, and derived generation fails closed. Secret is redaction, not encryption or access control.
- `Schema.parseRetainingInputWith` applies parse options while retaining input. Retained-input redaction matches
  declared secret field names and aliases ordinal-ignore-case, so a differently-cased secret key is masked on
  success or failure.

## Fixed

- Numeric index recognition no longer depends on runtime-specific `Int32.TryParse` behavior. Hexadecimal and
  underscore spellings stay object names on both .NET and Fable, and `0`/`00` sections retain both subtrees.

## AOT and trimming

- Every packable runtime library compiles with the F# `--reflectionfree` option, so library code cannot reintroduce
  reflection-backed structural formatting or `%A`. A package test scans the shipped assemblies for printf use.
- `SchemaGenerationError` has stable explicit text, and `Reified.Schema.Testing` round-trip diagnostics use the schema
  and JSON renderers instead of structural formatting.
- The NativeAOT probes for Result, Constraint, Refinements, and Schema treat every warning as an error, including
  IL2104 and IL3053 summary warnings from FSharp.Core, and publish cleanly with both `field` and `fieldAs`.
